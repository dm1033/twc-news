SAFETY OVERRIDE — TWC News Tab Publisher
Not installed. Paste this over the feed-writing rules only if you choose to.
This text does not publish a briefing, a LinkedIn post, or a GitHub commit by itself.

Read history from this repository, not from memory and not from a 20-post file alone:
- archive/feed.json in dm1033/twc-news (full list)
- posts/<id>.json in dm1033/twc-news
- feed.json in dm1033/twc-news only to notice a valid post that is not in the archive yet

Do not treat dm1033/twc-website or dm1033/twc-netlify-clean-pages as the history copy.
Those paths are on the push list today, so a backup written to the same feed.json path is overwritten with them.

Duplicate test, Europe/London:
- If a stored post already has today's London date, push nothing.
- If the new briefing's first source URL is the same as the first source URL of the newest stored post, push nothing.
- A source URL that appears on an older, different date is not a duplicate. Do not drop those older posts.

The new post, when there is one, needs id, date, kicker, title, excerpt, tags, linkedinReady, and body.
The id starts with today's London date. The body is the full briefing.
Reject your own draft if it is empty, shorter than a real briefing, or any of:
PLACEHOLDER, SEE_FILE, FULL_CONTENT, "content too large", "see /tmp".

Push with push_files only when the JSON parses. Push only:
1. dm1033/twc-news posts/<id>.json — the one new post
2. dm1033/twc-news archive/feed.json — every stored post plus the new post, newest first, never fewer than the archive you read
3. dm1033/twc-news feed.json — at most the newest 20 posts, valid JSON, same fields

If the full archive does not fit in the output, push only posts/<id>.json.
Do not push a shorter archive/feed.json. Do not push a placeholder. Do not push an empty posts array.
Leave feed.json unchanged in that case. A later capture step stores the single post file into the archive.

Do not push feed.json in dm1033/twc-website or dm1033/twc-netlify-clean-pages until the production page reads archive/feed.json and keeps the longer copy of each id.
The live Netlify file /assets/news/feed.json is a separate 31-post fallback dated 2026-11-02. Overwriting it with a 20-post file removes ids from that fallback.

Never delete a post. Never replace a stored id with a shorter body.
On push failure, stop. Do not retry by writing placeholder text into a feed file.

This override does not block a direct push. A token that can push_files to main can still upload a bad feed.json until a GitHub ruleset refuses direct pushes, with nobody bypassing it.
